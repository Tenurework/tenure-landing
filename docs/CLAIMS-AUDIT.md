## DO NOT ADD (pre-empting the natural next bullets)

- **Separation of duties.** `packages/authorization/src/policies.ts` has `notOwnRequest` / `notOwnReimbursement` and they're tested — but `decide()` is called in exactly one production location, `lib/authz/navigation-capabilities.ts:146`, for *menu visibility*. In the shipped approval path, `availableActions` computes `isRequester` and never uses it to exclude: at PENDING_OSE any OSE member may approve, so an OSE member holding an ACTIVE club president seat can submit (gate-skipping to PENDING_OSE) and then approve their own request end to end.
- **Self-serve configuration / "configure your own system" / System Studio.** The Studio is read-only by design and its own comment explains why (tenant overlays are files, not a config store). `Tenure-live`'s README states outright that the configuration engine, module runtime, blueprint system and System Studio "are not built yet" — and that is the repo that deploys production.
- **Per-customer AI keys, spend caps, quotas, or per-tenant AI opt-out.** One global `ANTHROPIC_API_KEY` serves all tenants, injected as a plaintext ECS env var (`ecs.tf:196` uses `value =`, not `valueFrom`). These exist only as prose in the architecture doc.
- **Two-way calendar sync.** The only `CalendarSyncProvider` implementation is `IcsFeedSync`, which implements neither `push` nor `pull`.
- **Row-level security.** Query-layer enforcement, not Postgres RLS. See B15.
- **SOC 2 beyond roadmap.** `Governance.tsx:56` currently reads `"SOC 2 roadmap, in progress"` — honest as written. Preserve that phrasing deliberately; do not upgrade it. (The only occurrence of "SOC 2" in either repo is inside a doc; there are no controls, evidence artifacts, or policy documents in `infrastructure/` or `.github/`.)
